# コンテンツ警告と相談窓口案内の方針

本作は「人を自死に至らせる怪異」を扉として、残された者の取り返しのつかなさを描く。
以下は開発中に守る描写制約と、リリース時に組み込む警告・案内の方針を定める。

## 1. 描写制約（開発中、全テキスト・全演出に適用）

| 禁止 | 代替 |
|---|---|
| 自死の方法・手段（器具・場所・手順・状態）を具体的にも暗示的にも描く | 「そうなってしまった」「もういない」。事後の生活の痕跡（靴、夕飯の匂い、乾かない洗濯物、未返信）と周囲の反応だけで伝える |
| 死の場面そのものを描く | 常に事後。発見現場も「場所」としてしか描かず、時間を飛ばす |
| 怪異が人を死に至らせる過程を手順・方法として描く | 「連れて行かれた」「帰ってこなかった」という結果と噂話のみ |
| 自死を救済・解放・美化として描く | 残された者の側から描く。蓮の母、トキ、澪の視点を必ず置く |
| 主人公の「捧げる」行為を手順として描く | 「頷いた」「先に帰った」の間を空白にする。真相版でも空白を埋めない |
| 終幕で澪が悠を討つ場面の方法・状態 | 「町の外へ出さない」「告発する」。翌朝の事後（橋のバリケード、揃えられた靴）のみ |

- テキストレビュー：`messages.json` の全エントリを PR ごとに上表で確認する。疑わしい表現は削る側に倒す。
- 語彙の禁止リスト：具体的な手段を示す名詞・動詞は `docs/` に列挙せず、レビュー時に個別判断する（列挙自体が手段の記述になるため）。
- 「見せないことが最も怖い」を演出の基準にする。空白・無音・不在で作る。

## 2. リリース時の警告表示（実装済み。文言はタスク7 で確定）

1. **初回起動時**、タイトルの前に全画面でコンテンツ警告を表示する（`content_notice` の `startup` モード）。表示は必須で、決定で閉じられる（読み飛ばしは可。表示直後の 0.8 秒は入力を受けず、押しっぱなしで消えないようにする）。既読を `user://system.json` に記録し、2 回目以降の起動では出さない。
2. 文言（`ui_notice_body`）：「本作には、自死とその喪失にふれる描写、追われる怖さ、心を操られる描写が含まれます。死の場面や具体的な方法は描きません。このお知らせは「設定」からいつでも見直せます。」脅かさず淡々と。メタ演出（ノイズ、画面の乱れ、話者の割り込み）はしない。
3. **設定画面**「コンテンツに関するお知らせを見る」から再表示できる（`replay` モード。既読は記録しない）。
4. **相談窓口案内**：警告画面の下段に「つらいときは、話せる場所があります。」に続けて、配信地域ごとの相談窓口を最大 3 件表示する。窓口は `data/locale/<lang>/support.json` から読む（§5）。一覧が空のあいだは「（相談窓口は、配信地域が決まってから掲載します）」の一行を出す。
5. Steam ストアページの「成人向けコンテンツの説明」欄にも同趣旨を記載する（`docs/STORE_PAGE.md`）。

## 3. ゲーム内の運用

- 8/30 夜の隠蔽リスト提示と 8/31 のエンディングの直前に、短い暗転と無音を置き、プレイヤーが一呼吸できるようにする。
- エンディング後、スタッフロールの前に相談窓口案内を再度表示する（実装済み：`end_game` → `content_notice` の `after_ending` モード。`ui_notice_title_after_ending` / `ui_notice_body_after_ending`。既読は記録しない）。
- 「裏面」モード（周回）でも警告は省略しない（実装済み：タイトル「裏面から」→ `replay` モードで表示してから開始）。

## 4. 実装への反映箇所

| 項目 | 実装タスク |
|---|---|
| 初回警告画面・設定からの再表示 | 済（`scenes/ui/content_notice.tscn`、`scripts/ui/title.gd`、`scripts/ui/settings_menu.gd`） |
| `user://system.json` への既読記録 | 済（`SaveManager.mark_content_notice_seen`） |
| 相談窓口の読み込み口 | 済（`MessageResolver.load_support` → `support_entries()`。`data/locale/ja/support.json`） |
| エンディング後の案内 | 済（`end_game` → `after_ending` モード） |
| 文言の確定・ストア文案 | 済（feat/content-notice、`docs/STORE_PAGE.md`） |
| 窓口の掲載 | **未**（§5 の手順で確認後に `support.json` へ記入） |

## 5. 相談窓口の掲載手順

- ファイル：`data/locale/<lang>/support.json`。`entries` の要素は `{name, contact, hours?, note?}`。`meta.verified_at` に確認日（YYYY-MM-DD）を書く。`docs/tools/validate_data.py` が、窓口があるのに確認日が無い場合をエラーにする。
- 手順：(1) 掲載候補の名称と連絡先を一覧にして、開発者が確認する。(2) 名称・番号・受付時間を **各窓口の公式の一次情報で照合** し、確認日を書く。(3) 記入して案内画面の表示を実機で確認する。(4) リリース前と、以後は半年ごとに再確認する（番号・受付時間は変わる）。
- 書かないこと：未確認の番号、検索結果の引き写し、民間の有料サービス、宗教団体、特定の政治団体。公的機関または公的機関が案内している窓口に限る。
- 表示：最大 3 件。多いほど読まれないので、電話・チャットなど手段の異なる 2〜3 件に絞る。
- 文言は「つらいときは、話せる場所があります。」で固定し、「相談してください」のような命令形は使わない。
